# Stage 10 — разделение кода по экранам

## Контекст

После Stage 9 пользователь подтвердил прохождение тестов и сборки. В выводе Vite основной JS-файл составлял примерно 568 kB до gzip и превышал стандартный предупредительный порог в 500 kB. Это не ошибка сборки, но подходящий сигнал проверить, не загружаются ли крупные неосновные экраны до первого открытия.

## Изменения

- `StatisticsScreen`, `WalletScreen`, `GoalsScreen` и `SettingsScreen` подключены через `React.lazy()` и динамический `import()`.
- Для каждого лениво загружаемого экрана добавлен локальный `Suspense` fallback с доступным статусом загрузки.
- Главный экран остаётся обычным статическим импортом — он нужен сразу при запуске.
- Посещённые вкладки, как и прежде, остаются смонтированными после первого открытия, чтобы переключение вкладок не сбрасывало состояние самих экранов.
- Для ленивых экранов сохранена мемоизация, чтобы обновление несвязанных состояний `App` не вызывало лишние рендеры.
- Не изменялись Dexie, схема данных, финансовые расчёты, резервные копии, зависимости и дизайн экранов.

## Ожидаемый эффект

React `lazy()` позволяет откладывать загрузку кода компонента до первого отображения, а `Suspense` показывает локальный fallback во время загрузки. Поэтому начальный JS chunk должен стать меньше и браузеру потребуется меньше кода для первичного запуска.

Это не гарантирует уменьшение общего размера всех JavaScript-файлов. Текущая PWA-конфигурация предварительно кеширует JS-ресурсы, поэтому общий объём кеша для offline-работы может остаться похожим. Цель — разделить начальный код и код экранов, которые не нужны до первого перехода.

## Ручная проверка

1. Запустить `npm run dev -- --host` и проверить, что главная открывается без изменений.
2. Перейти в Статистику, Кошелёк и Цели. Каждый экран должен загрузиться; краткое сообщение ожидания допустимо только пока загружается chunk.
3. Изменить локальный фильтр экрана, перейти на другую вкладку и вернуться: состояние ранее смонтированной вкладки должно сохраниться.
4. Открыть Настройки, проверить переходы по разделам и раздел «Данные и бэкап».
5. Проверить добавление транзакции, перевод между счетами и открытие карточки транзакции.
6. Запустить `npm run build` и сравнить основной JS chunk и остальные chunks с Stage 9. Не повышать `chunkSizeWarningLimit` ради подавления предупреждения.
7. Проверить production-сборку через используемый способ запуска/preview; Vite dev server сам по себе не подтверждает split в production.

## Проверки в среде подготовки

Синтаксическая транспиляция всех 94 файлов TS/TSX прошла без синтаксических диагностик. Полные ESLint, TypeScript typecheck, Vitest и production build Stage 10 не выполнены в среде подготовки: для этого требуется проектная установка npm-зависимостей. Изменение не считать проверенным релизом до успешных команд в рабочей копии.
